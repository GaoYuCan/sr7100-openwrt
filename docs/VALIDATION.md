# 验证记录

本页区分原适配的实机验收与公开源码的重新构建。2026-10-11 整理发布时没有连接路由器，也没有将重新构建的产物刷入设备。

## 发布前重建

| 项目 | 结果 |
| --- | --- |
| 内核源码恢复 | 从 Linux 6.12.94 原始压缩包应用补丁；672 个变更文件逐个与实测构建树的哈希一致 |
| 内核与以太网 | Image、内核模块、`zx279133.ko`、`sr7100-gephy.ko` 编译通过 |
| 无线 | 使用锁定版本与包补丁，compat、cfg80211、mac80211、mt76、mt76-connac-lib、mt7996e 编译通过 |
| 设备树 | 使用本机私有 EEPROM，RAM 与 installed 两种 DTB 均编译通过；产物不公开 |
| 容器 | 仓库 Dockerfile 构建通过；无线构建及离线测试在该容器中通过 |
| NAND 边界策略 | 201,158 项检查通过 |
| 端口归属与共享生命周期 | 65,792 项检查通过 |
| 核心持久化 | 首次保存、旧布局迁移清理、替换、配置拒绝、损坏归档、空间不足、8 个进程强制终止边界及恢复清理通过 |
| 离线 rootfs 安装器 | 模拟 OpenClash 文件结构的首次安装与重复安装通过；核心 RAM 链接、GeoSite 种子、单份更新钩子和回退核心检查通过 |

软件测试使用临时主机文件系统和模拟核心。它验证提交策略及指定失败路径，不能证明真实 NAND 任意时刻断电都不会丢数据。

## 已有实机记录

- A25/A26：原厂 U-Boot 自主启动、普通重启、真正断电重上电及配置保留。
- 三网口：端口映射、LAN1/WAN 与 LAN2/WAN 收发、NAT、隔离和 OpenClash DNS/透明代理。
- 天线接回之后：双频关联、DHCP、双向文件传输校验与重连；没有做极限吞吐结论。
- 扩容前：128 MiB ECC 数据备份及分块读回比较；在 B 系统载荷和 Plugin 区域进行写入、挂载、随机文件校验、原数据恢复和字节比较。
- 扩容后：保留 B U-Boot 与救援定位信息，Plugin 持久保存核心，重启及冷启动通过。
- 随后的单核心策略：通过 OpenClash 更新脚本切换 Mihomo v1.19.31 → v1.19.32，普通重启后确认版本、单份归档及代理请求。该次策略变更后没有另做一次真实断电测试。

A 版本头损坏后定位 B U-Boot 的分支使用原始早期引导代码执行仿真验证，未在真机故意损坏 A 头。保留 B U-Boot 也不代表存在完整的 B Linux 回退系统。

长期稳定性、极限吞吐、完整 IPv6、真实 PPPoE 接入、通用 sysupgrade 和任意新版 OpenClash 整包更新仍未验收。
